Autonomous Camera & Motion Control

Team 68 · Senior design · 2024–2025 · Machine learning & embedded integration

Project overview

The team built a camera system that reacts to driveway motion, pans toward the active area, applies a property-boundary mask, and analyzes recorded video for known and unknown faces. My work connected perception, event logic, and embedded motion control.

TensorFlowOpenCVJetsonPython concurrencyAVR CPID

My contribution

I worked heavily on the CNN and recognition pipeline, helped with threading and PIR integration, and contributed to filter application, Boolean decision logic, and serial-command selection. I also worked on the microcontroller ISR and PID loop for the motor.

Technical implementation

CNN detection and recognition

My detection notebook builds a VGG16-style network from scratch, with separate face-classification and bounding-box outputs. It uses batch normalization, L2 regularization, dropout, and a training/augmentation workflow. The recognition pipeline compares face embeddings against enrolled profiles and leaves unmatched faces labeled unknown.

Face-recognition matching

I worked on the project’s nearest-neighbor recognition approach. The recognition notebook and Jetson implementation compare facial encodings with cosine similarity, select the best matching stored profile, and apply a threshold before accepting a known identity. Unmatched faces remain unknown.

Linux processes and threading on the Jetson

The Linux-based Jetson runs Python processes for serial I/O, hardware management, image capture, image processing, recording logic, the web server, and file cleanup. A separate thread performs facial analysis on completed recordings. Locks protect shared latest-frame buffers; queues carry commands, responses, and completed-video paths. This is Linux process/thread coordination; FreeRTOS belongs to my separate IMU project.

PIR logic and the serial boundary

Three PIR inputs are thresholded and held briefly to reduce rapid changes in the motion flags. Boolean combinations select a pan target or deliberately keep the current position. A single worker owns the 38,400-baud UART. It formats ASCII move commands as CO0 plus three hexadecimal position digits and a newline; CR0000 requests position readback. Per-client response queues return each reply to its requester.

Position-aware privacy masking

The masking path requests the encoder angle, maps image columns into the panorama’s angular coordinates, and applies the corresponding slice of the property mask. The processed frame is used for both video output and the shared stream buffer.

ATtiny3226 interrupt-driven motor control

The ATtiny3226 runs bare-metal AVR C. Its periodic ISR reads the magnetic encoder over I²C, computes an integer PID-style output, and updates PWM and motor direction. The final report describes 512 updates per second. Wrapped position error, a deadband, bounded integral accumulation, and output limits support the loop. UART commands run through the main loop. The final tuning used proportional-only control; integral and derivative gains were zero.

Development & improvements

Camera startup → continuous acquisition

Restarting the capture pipeline for each panorama or recording caused inconsistent frame timing relative to encoder readback. The final design kept capture running in its own process and enabled masking/recording with an event. The integration report describes reduced startup lag and more consistent frame handling.

Competing UART requests → one serial worker

Panorama setup, PIR motion, privacy masking, and manual control all needed the motor interface. One worker owns the UART, formats commands, and returns responses through per-requester queues. This is an integration improvement I helped with.

Raw encoder readings → calibrated angle

The team measured nonlinearity and stored a correction lookup table in MCU flash. The corrected angle feeds control and masking. Final validation reported approximately 0.6° angular repeatability, measured with a laser on a wall 16 ft away; this is a team hardware result.

Noisy PIR readings → stabilized motion decisions

The PIR logic holds an active state for roughly 0.3 seconds after threshold activity, reducing rapid flag changes. Boolean combinations map the three sensor inputs to pan targets, while ambiguous combinations keep the existing position.

Final product & validation

The final system combined the camera, PIR boards, motorized gimbal, Jetson, power electronics, batteries, and Wi-Fi in a 3D-printed enclosure. The PC application supported setup and viewing, while the Jetson coordinated acquisition, recording, privacy masking, and recognition.

Final result & next steps

The team produced a working integrated camera in a 3D-printed enclosure, with PIR sensors, a motorized pan mechanism, Jetson processing, a PC interface, recording, and position-aware privacy masking. The report demonstrates motion responses and masked live frames, and records roughly 0.6° pan repeatability. My contributions centered on machine learning, sensor/serial integration, masking logic, and the ISR/control loop. Remaining improvements included tighter capture/angle synchronization and stronger real-world recognition evaluation.
