Verilog & DSP-Based Control

Coursework · Digital design & ECEN 442/742 · Student designer · DSP lab coauthor

Project overview

I completed the class labs covering combinational logic, arithmetic, sequential circuits, timing, and state machines. In a separate DSP-based motion-control lab, my partner and I programmed a two-phase stepper motor and optical homing input using embedded C.

VerilogTestbenchesFSMsVivadoEmbedded CTI C2000

My contribution

I completed the Verilog design labs for class and worked with Lyric Haylow on the DSP-based stepper-motor lab, including the embedded C implementation, experiments, and report.

Technical implementation

Combinational and arithmetic RTL

I worked through multiplexers, decoders and encoders, full adders, add/subtract logic, and ALUs, then built larger arithmetic functions from smaller modules. Carry-lookahead design made the generate/propagate relationships explicit and extended a 4-bit arithmetic block into a hierarchical 16-bit adder. This connected Boolean equations, module interfaces, and the path a carry takes through a circuit.

Sequential logic and control

The labs progressed from latches and flip-flops to synchronous adders, counters, clock dividers, debounce circuits, and a digital clock. A traffic-light controller combined stored state, elapsed-time conditions, and an external sensor request. The design separates clocked state updates from combinational next-state and output logic; input synchronization handles the boundary between an external signal and the FPGA clock.

Verification as part of the design

Testbenches apply inputs and compare circuit outputs with expected behavior, while simulation waveforms reveal when signals and states change. Arithmetic checks exercise operands and carry behavior; sequential designs require attention to clock edges, reset, and transition timing. The coursework also included Vivado projects and constraints that connect RTL signals to FPGA hardware.

Stepper-motor excitation

The DSP lab configures GPIO pins and writes set/clear registers to produce four full-step excitation patterns. Half stepping inserts intermediate winding states for an eight-pattern sequence. Reversing the sequence reverses travel direction.

Homing through an external interrupt

An optical input on GPIO33 is connected to XINT1, with falling-edge detection and six-sample input qualification. The documented homing routine stops the motor on the event and acknowledges the PIE interrupt group. A volatile reset flag lets the motion loop respond to the event and end the active sequence. This connects a physical reference position to the firmware’s movement logic.

Electrical sequencing has a mechanical limit

The lab varied delays to observe where the scanner head stopped moving correctly. The report records jamming around 1,750 µs in full-step mode and 900 µs in half-step mode. These are observed failure thresholds in that setup, rather than a rated operating speed.

Selected logic & code

These short examples connect the lab topics to their implementation. The Verilog fragments illustrate the coursework I completed; the embedded C excerpts come from the stepper-motor report I coauthored with Lyric Haylow.

Carry lookahead: calculate carries from generate and propagate

Each bit either generates a carry or passes an incoming carry onward. Expanding the carry expressions lets the circuit calculate them directly from the inputs. The labs extended this idea from a 4-bit adder to a hierarchical 16-bit design.

assign propagate = a ^ b;
assign generate_bits = a & b;
assign carry1 = generate_bits[0] | (propagate[0] & carry_in);
assign carry2 = generate_bits[1]
              | (propagate[1] & generate_bits[0])
              | (propagate[1] & propagate[0] & carry_in);

Illustrative RTL for the carry-lookahead coursework; signal names are simplified.

Synchronize an external input before using it in an FSM

The clocked stages reduce the risk that an asynchronous input disrupts the controller. A traffic-light FSM then combines a synchronized sensor request with elapsed-time conditions to choose the next state. State registers update on clock edges; combinational logic determines the next state and light outputs.

always @(posedge clk) begin
    sensor_stage0 <= sensor_input;
    sensor_stage1 <= sensor_stage0;
    sensor_stage2 <= sensor_stage1;
end
assign sensor_sync = sensor_stage2;

Illustrative RTL explaining input synchronization; the linked lab archive is credited to Kalclavia.

Drive one winding state with GPIO set/clear registers

This function selects one full-step excitation pattern on the four driver inputs. Calling the four patterns in order moves the scanner head; reversing that order reverses direction. The delay between calls controls the commanded stepping rate.

void step1() {
    GpioDataRegs.GPBSET.bit.GPIO41 = 1;
    GpioDataRegs.GPBCLEAR.bit.GPIO43 = 1;
    GpioDataRegs.GPBSET.bit.GPIO42 = 1;
    GpioDataRegs.GPACLEAR.bit.GPIO16 = 1;
}

Excerpt from the supplied ECEN 442/742 Lab 6 appendix, coauthored by Dennis Nguyen and Lyric Haylow.

Respond to the optical home sensor

GPIO33 supplies the optical input to XINT1. Falling-edge detection and six-sample input qualification establish the event boundary. The handler de-energizes the motor outputs, sets a flag for the motion loop, and acknowledges the interrupt group so subsequent events can be serviced.

volatile Uint16 reset = 0;

interrupt void isr_zeroposition(void) {
    reset = 1;
    motor_stop();
    PieCtrlRegs.PIEACK.all = PIEACK_GROUP1;
}

Excerpt from the coauthored lab appendix. The reset flag connects the ISR with the motion routine.

From four full steps to eight half steps

Half stepping inserts single-phase states between the two-phase states. This gives smaller angular increments for the same motor and connects the firmware sequence directly to the scanner head’s motion.

Excitation sequence used in the lab (A/B describe winding polarity)
ModeForward sequenceWhat changes
Full stepA+B+ → A−B+ → A−B− → A+B−Four two-phase states
Half stepA+B+ → B+ → A−B+ → A− → A−B− → B− → A+B− → A+Eight states, alternating one and two energized phases

Development & improvements

Synchronize an external signal

An asynchronous input needs a deliberate boundary before synchronous state logic uses it. That is a hardware synchronization problem, separate from a CPU interrupt handler.

Coordinate firmware and mechanics

A correct GPIO pattern is only one requirement. The winding current and mechanical load also need enough time to respond before the next commanded state.

Full stepping → half stepping

Adding intermediate winding states changed a four-pattern full-step sequence into eight half-step patterns for finer positional increments. Both modes were tested against the scanner’s mechanical response as delays were reduced.

Final result & next steps

Coursework spanning RTL construction and simulation, plus a documented embedded C lab demonstrating full/half stepping, direction reversal, optical homing, and timing-limit experiments on a TI C2000-family platform.
