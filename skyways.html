Skyways HIL Test Platform

Skyways · Summer 2026 · Systems Engineer Intern

Project overview

Aircraft availability and manual checks made avionics validation difficult to repeat. I built a bench platform that commands real avionics hardware, measures its electrical outputs through separate hardware, and produces traceable results without attaching an aircraft.

PythonEmbedded C++PyQt5MAVLinkCAN / DroneCAN

My contribution

I designed, built, and operated the HIL apparatus; developed the test platform and operator GUI; integrated measurement hardware and firmware; and assembled wiring harnesses. The work included V2/V3 compatibility, an intermediate adapter box, modular bench hardware, and debugging across electrical and software interfaces.

Technical implementation

The system and operator GUI

A Python core coordinates device discovery, protocol adapters, declarative tests, and result logging. The PyQt5 interface includes device health checks, test selection, measured-versus-expected details, and run results. The health check enumerates bench devices and confirms deployed software. Logical device roles decouple each test from the physical port used on a particular bench.

Measure the output independently

Arduino Mega measurement boards read PWM signals directly. A LabJack T7 and MUX80 read analog channels; Feather M4 firmware emulates CAN and DroneCAN devices. The command path and measurement path stay separate, so a device’s own status report is not the sole evidence that its electrical output is correct.

Intermediate box and differential PWM

The intermediate box connects the HIL harness to the V3 AV box with one-to-one signal routing. Differential receiver hardware converts V3 differential PWM outputs into single-ended signals the bench can measure. A modified, 3D-printed case, lid, and receiver platform enclose the adapter hardware.

Modular pegboard and peripheral connections

The pegboard mounts two Arduino measurement boards, two Feather M4 CAN/UART boards, the LabJack, probe PCBs, a central USB hub, and shared ground terminals. A peripheral rail exposes 5 V, 12 V, UART, DroneCAN, and engine CAN connections so additional devices can be connected and tested.

Make the platform maintainable

Channel maps and V2/V3 suites are configuration data. Wiring documentation is generated from the channel maps, and live firmware-map checks warn when host configuration and board labels disagree. Simulated adapters let the core and GUI run without occupying the physical bench.

Linux readback, service sequencing, and logging

The test platform queries the Jetson Orin over SSH to confirm downstream behavior. Some tests need an onboard service stopped to access its serial port; others need it running to read its output. The runner groups tests by those requirements and changes service state between groups. Runs produce CSV data and summaries, and the interface supports adding operator notes during testing.

Development & improvements

A software symptom, an electrical cause

Attenuated PWM readings on a group of motor channels traced to indicator LEDs loading the probe PCB. Removing the LEDs and verifying continuity and common ground corrected the measurement path.

A healthy-looking reading can still be wrong

A wiring change could leave firmware labels and host pin maps out of sync. Automatic map comparison addressed the risk of silently attributing a valid signal to the wrong motor.

Respect voltage domains

A radio interface exposed a 5 V / 3.3 V mismatch. Moving the UART function to a native 3.3 V controller aligned the interface with the radio.

Final result & next steps

Delivered an assembled, operator-driven bench for V2 and V3 AV-box validation, with analog pinout checks and closed-loop tests across peripheral interfaces. The project record lists 16 tests in the V2 suite and 13 in V3, from 18 registered tests overall; the 27 analog channels include 14 active in V3. The manual-control view remained a beta feature. Next steps included stronger strain relief and permanent probe connections, replacing the prototype intermediate-box enclosure, expanding live signal monitoring, and eventually extending to full aircraft-level validation.
